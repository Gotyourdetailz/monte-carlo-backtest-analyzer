# Phase 1 — UI Design Contract: Light-Mode Panel Sweep

> Visual and interaction contract for the token-correctness sweep. Generated by gsd-ui-researcher.
> This phase is NOT net-new UI. It is a migration: ~24 analyzer panels currently hardcode dark
> hex values and break in light mode. The B1 theme engine already defines a full light+dark token
> set; this spec locks HOW corrected surfaces, text, semantic colors, shadows, and motion must
> look in BOTH modes so the planner can write deterministic migration tasks.

## Shadow Tokens (New — Required Addition to `tokens.ts`)

**Decision:** Add two shadow tokens to `src/theme/tokens.ts` (both `darkTokens` and `lightTokens`
maps) and regenerate `theme.css`. The current `rgba(0,0,0,0.4)` shadow in `ui/card.tsx` is
visually over-heavy on white light-mode surfaces. C6 requires "flat 1px-hairline surfaces" with
"subtle-shadow" — not zero shadow, but a mode-appropriate one.

**New tokens to add to `tokens.ts` (in both dark and light records):**

```ts
// In darkTokens:
'--shadow-sm': '0 1px 2px rgba(0,0,0,0.35)',
'--shadow-md': '0 4px 12px rgba(0,0,0,0.40)',

// In lightTokens:
'--shadow-sm': '0 1px 2px rgba(0,0,0,0.08)',
'--shadow-md': '0 4px 12px rgba(0,0,0,0.10)',
```

**Consumption pattern:**

| Usage | Class |
|-------|-------|
| Card default shadow | `shadow-[var(--shadow-sm)]` replaces `shadow-[0_1px_2px_rgba(0,0,0,0.4)]` in `ui/card.tsx` |
| `.glass-card` in `index.css` | `box-shadow: var(--shadow-sm)` replaces `rgba(0,0,0,0.4)` |
| Panel-level cards in components | `shadow-[var(--shadow-sm)]` |
| Modals / elevated surfaces | `shadow-[var(--shadow-md)]` |
| Glow effects (`--glow-*`) | Unchanged — glow tokens are decorative accents, not structural shadows |

**Source:** C6 constraint; orchestrator open gray area #1; `ui/card.tsx:9` as canonical exemplar.

## Surface Treatment Contract

This phase establishes the following surface rules across ALL analyzer panels:

### Borders

All panels use a flat 1px hairline border:

```
border border-[var(--border)]
```

- No double borders.
- No gradient borders.
- No `border-2` or thicker borders on panel containers (inputs may use focus `border-[var(--accent-blue)]`).

### Shadows

- Panel cards: `shadow-[var(--shadow-sm)]` (new token; see Shadow Tokens section above).
- Modals / dialogs: `shadow-[var(--shadow-md)]` (new token).
- Glow accents (`.glow-border-blue` etc.): KEEP as decorative-only — not added to surfaces during this sweep.
- Hover lift effect (`glass-card-hover`) retains `translateY(-1px)` + `shadow-[var(--shadow-md)]` replacing the current `rgba(0,0,0,0.3)` value.

### No backdrop-filter

Zero occurrences of `backdrop-filter` or `backdrop-blur` anywhere in `src/components/**` (C6).
The existing `sanity_revamp_smoke.test.ts` already asserts this for `src/components/ui/`. The
Phase 1 guard test (see Verification section) must extend this assertion to all `src/components/**`.

### Corner Radius

All panel cards use `rounded-[var(--radius)]` (= `0.5rem` = 8px). Do not change during sweep.
Sub-elements (badges, inputs, inner cards): existing classes preserved; standardize on `rounded-lg`
(8px) for consistency but this is not a blocker for phase completion.

**Source:** REQ-surface-motion-finalization acceptance criteria; C6; orchestrator open gray area #1.

## Motion Contract

This phase includes a motion AUDIT (verify timings) not a motion redesign. The motion system
is already defined in `src/index.css` via CSS custom properties and `@media (prefers-reduced-motion)`.

### Timing Tokens (Already Defined — Do Not Change)

| Token | Value | Use |
|-------|-------|-----|
| `--dur-fast` | 150ms | Button press, hover state changes |
| `--dur-base` | 220ms | Standard transitions (panel color changes) |
| `--dur-slow` | 320ms | Entry animations |
| `--dur-exit` | 160ms | Exit/dismiss |

### Rules

- Transitions: 150–250ms only (C6). The `duration-300` instances found in components (`RunHistoryPanel`) are at the outer boundary — flag for review but not a blocker.
- `duration-500` (Sidebar.tsx:209 `transition-all duration-500`) — ASSUMPTION (confirm): this is the sidebar expand/collapse which at 500ms violates C6 (≤250ms for transitions). Flag for correction to `duration-300` max.
- Entry animations: ≤300ms. `fadeInUp 0.35s` in `.animate-fade-in-up` — exceeds by 50ms; correct to `0.30s` during this sweep.
- No perpetual animation in `/app` panels (C6). Shimmer `.animate-shimmer` is a skeleton loader — acceptable only as a loading state. Assert it is NOT applied to idle UI states.
- `prefers-reduced-motion` is already globally handled in `index.css` with `animation-duration: 0.001ms !important` — this is CORRECT and must not be removed.

**Source:** PROJECT.md C6; `src/index.css` motion tokens; orchestrator open gray area #4.
